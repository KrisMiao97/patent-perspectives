# 整篇分析与专题研究

在导出阅读任务、安排代理分工、复核或修订已有报告时读取。本流程保留技能原有主体、来源、版本和实际阅读范围要求；“整篇”指明确所用文献和版本的完整阅读任务，不自动把完整权利要求阅读扩大为完整说明书、附图及产品研究。

## 一个完整任务

每件纳入的技术申请建立一个任务包：所选主文献全文、来源与版本、权利要求或段落定位，以及可取得的同版本说明书和附图入口。主文献仍优先完整权利要求，说明书按实际理解需求补读；需要全说明书或全部附图才能支持某个结论时，继续补读并记录。不同公开/授权版本和各国同族文本分开，不能拼成同一来源。

同一篇由一个负责者形成完整解释。不要把固定字符数片段分给多个代理后拼接结论。可以按篇并行，另由独立审查者复核；任务输入仅携带必要产品背景、研究目标和本件材料，不持续叠加其他专利原文、工具日志和排版讨论。程序提供材料与进度，不自动调用模型、测量注意力或调度代理。

`export-work` 默认提供完整 `primary_document` 和定位资料；原数据库的旧分段保留为兼容覆盖索引，不作为独立研究任务。新导入主文献使用覆盖全文的单个兼容区间。引用继续使用真实权利要求号、段落、页码、图号与字符位置，证据追溯无需固定长度切块。

任务中的 `material_availability` 区分已经附入的全文、库内可补读的说明书及尚未取得材料。图件没有附入时如实标明，不能因为存在来源网址就宣称已经看过附图。独立复核包另提供可取得的同公开号完整说明书，但实际补读范围仍由审查者记录。

如需先处理较短材料，可用 `export-work --output FILE --max-primary-characters N` 设置本批主文献字符上限。超过上限的整篇任务进入同目录的 `FILE.deferred.json`，不切片、不截断、不从覆盖分母排除；后续仍需处理。此参数是宿主选定的筛选条件，不是模型 token 安全阈值或自动上下文调度。

## 容量与连续阅读

先确认任务材料、必要图片、分析输出及补查能否放入当前实际可用上下文。采用真实长度和小样本验证判断，不能把模型标称窗口或固定字符比例当成精度保证。

可容纳时完整加载所选主文献。超长或附图很多时仍保留同一个任务：连续阅读原有章节、完整实施例或完整工作过程，保存术语、部件关系、适用条件、待核实引用和实际读区间，最终合成为一份贯通全文的解释。区间是阅读记录，不是互不相干的分析结论。不得静默截断、以摘要替代未读正文，或省略片段后勾选整篇完成；容量仍不足以核清必要关系时保留未完成。

主文献阅读记录使用 `whole_document_review`，字段及尾文校验见 [host-review.md](host-review.md)。连续阅读必须说明原因，记录覆盖全文的区间；辅助说明书仍另记 `support_documents/read_regions`。原文有正文、公式或图片缺陷时，走来源拒绝与补证流程，不能通过改变阅读模式绕过。

## 单件解释与独立复核

逐件结果应让读者说清：用于什么场景、部件装在哪里、如何连接、何时触发及怎样动作、依赖什么条件。区分权利要求限定、实施例选择、原文宣称的功效与分析推断。八字段用于记录证据，不能替代连贯说明；没有披露的内容保持未知。

独立审查者先查看原始材料并形成自己的判断，再与初稿比较，核查以下内容并记录原文依据：

- `mechanism`：结构、连接和工作过程是否正确。
- `conditions`：限制条件、从属关系和触发条件是否遗漏。
- `embodiments`：是否把替代实施例错误拼成一个必备方案。
- `figures`：必要附图、公式和表格是否实际核对，图文是否一致。
- `source_attribution`：事实、推断、版本及功效来源是否分清。

每项可以 `pass`、`fail` 或有理由的 `not_applicable`。缺少决定结论的图片或原文，不能以不适用代替未取得。分析者与审查者须为实际不同的负责者，保留真实身份；不得由同一代理改名填表冒充独立审查。程序只能检查这些声明与来源是否一致，不能证明独立性或语义真伪。

发现错误后修订分析并重新复核。单件理解复核与原文引用校验分别计数；抽查可用于额外发现系统性问题，不能代替真实运行中每件技术申请要求的复核记录。

## 跨专利专题

选题、真实对照、公司相对位置和有限补证按[共同问题与比较研究](comparative-research.md)执行。先从产品关键功能和工程问题确定重要性，数量变化仅作为线索；围绕少数重点问题查深，不要求全部分类等深度。技术贡献、权利控制与产品表现分别求证，研究对象及用户用途不需要这些维度时不扩大范围。

根据用户研究目标及逐件发现建立明确问题，记录选取相关申请的理由。问题应要求解释具体差异或关系，例如哪些结构变化对应了某阶段的申请增加、相近方案为什么适用条件不同。不能把“总结这些专利”或三个读者角色名称当作已完成的研究问题。

需要结构化术语、逐项比较、路线关系与发现时，启用[问题驱动工作流](research-workflow.md)。其问题ID与本节质量计划共用；初始 partial/pending 底稿不算回答完成，answered 只能引用当前已通过独立审阅且答案一致的专题结果。该扩展不替代下面的单件及专题复核，也不自动安排代理阅读。

对每个问题，先提出可检查的候选解释，再比较真实方案，回读关键原文和必要图片，查找反例与其他解释，说明差异成立的条件。单件摘要仅用于定位；决定结论的原文必须可调回。发现前期分类、条件或版本错误时，更新逐件记录并重做受影响的比较。

没有找到可比方案时说明检索范围和不可比原因；没有找到反例时记录实际检查范围和结果，不编造反例。资料不足的答案可以保存，但不能计为问题已经解决。结论不得由申请数量、时间先后或文字相似直接推成技术提升、因果关系或商业壁垒。

## 研究质量记录

以下命令接受 `--input FILE`。详细错误以实际 CLI 为准，机器字段均填写真实审阅结果。它们不替代原始证据导入、逐件分析或角色结论。

复核者开始阅读前，运行 `export-quality-work --output FILE --review-packets DIR`，保存版本清单并逐件生成两个文件：`original-sources.json` 包含完整原文及来源，不含初稿结论；`draft-comparison.json` 单独保存被检查的原分析。先只把原文包交给复核者，保存独立观察后再提供初稿对照。每篇仍为完整任务，不能将全库原文拼成一个复核上下文。省略可选的 --review-packets 时只生成小型版本清单。

单件复核的 `analysis_fingerprint`、专题复核的 `plan_hash` 和 `population_hash` 均须取自实际审阅时的清单；导入缺少指纹或与当前版本不同都会被拒绝。资料或分析变化后，重新导出、重新审阅，再填写结果，不能给旧答案换上最新指纹来冒充重新复核。

### 单件复核：semantic-review-import

输入可为对象或数组。每条记录含 `application_id`、必填的 `analysis_fingerprint`、`analysis_author`、`reviewer`、`independent:true`、`reviewed_original_sources:true`、`result`（`pass` 或 `revise`）、非空 `evidence_ids` 和 `checks`。分析作者须与已存分析一致，审查者须为不同的实际负责者。`checks` 恰好包含上述五项，各项含 `status` 与非空 `basis`；`pass` 或 `fail` 还须填写本项 `evidence_ids`，并属于总引用集合。`source_attribution` 不能标为 `not_applicable`。

证据可以沿用本申请当前分析的证据，也可通过 `source_evidence` 提交复核者新发现的原文。每条新证据含独立 `id`、`document_id`、连续原文 `quote` 和精确 `locator`；可补充 start/end 或 source_text_hash。权利要求定位使用 `{"claim_number":2}`，说明书使用真实 `{"paragraph":"0038"}` 或 `{"source_span":true}`。新ID不得与原分析证据重名，并须在复核总 evidence_ids 及适用的检查项中引用。仅接受同申请、同公开号、同原文语言的合格未拒绝文本，不能借同族或另一授权版本举证。新证据独立保存在复核记录，不改初稿或其指纹，也不自动成为角色结论证据；修订分析时应正式补入相关证据并重新复核。若复核补读了说明书，只声明实际检查的引文区间，不冒称全书已读。

脚本核对实际审阅版本指纹；分析更新后旧复核过期，不能通过省略指纹重新导入。

### 研究计划：research-plan-import

输入对象为 `{"questions":[...]}`。每项含稳定 `id`、具体 `question`、非空 `application_ids` 和 `selection_basis`。计划创建时的哈希由脚本计算，无需预先提供；建立计划后再导出待审清单取得专题复核所需指纹。覆盖已约定的重点研究问题，保留真实选择理由。修改计划写明 `revision_reason` 并重新审查受影响结果，不能在临近交付时删除难题来提高完成率。

### 专题结果：research-review-import

输入可为对象或数组。每条记录含：

- `question_id`、必填的 `plan_hash` 和 `population_hash`、`status`（`resolved` 或 `insufficient_evidence`）、`answer`、`evidence_ids`。
- `comparison:{status,basis}`，status 为 `compared` 或 `not_comparable`；实际比较至少涉及两件申请，不可比须说明具体理由。
- `counterevidence:{search_scope,findings,impact}`，记录实际反例或其他解释检查及其对答案的影响。
- `conditions` 是非空字符串；`limitations` 是字符串数组，证据不足时不得为空。例如：`"conditions":"仅限本次已读版本及所述工况", "limitations":["未取得同条件性能测试"]`。另记录真实的 `analysis_author`、`reviewer`、`independent:true`、`reviewed_original_sources:true`、`review_result`（`pass` 或 `revise`）。

脚本核对实际审阅时的问题计划和资料集合指纹。问题变更、依据更新或分析修订后，旧结果不能自动沿用，也不能靠省略指纹重新绑定。`insufficient_evidence` 和 `revise` 会保留，但不计为研究完成；关键缺口另进入统一《分析记录与后续补充说明》。没有反例不必改成证据不足，前提是既有证据确实支持限定后的回答，且如实记录了检索边界。

真实运行要求有效的单件复核及研究计划内全部问题完成。历史分析保留并可以复用，但没有当前有效复核记录时，新研究质量验收仍未完成；不能把旧完成标签、字符串引用核对或内容条数当作补做的审查。结构、覆盖及声明检查通过不等于零错误，更不能据此生成准确率。

质量记录保存在 `quality_reviews`、`research_plan`、`research_reviews`，进入正式资料覆盖输出及数据复用包；问题状态和读者需要了解的缺口同时汇入统一《分析记录与后续补充说明》。不能只在临时对话中声称已复核而不保存记录。

专题完成后按[报告组织](reporting.md)将答案及其条件写入正文，并用角色结论的 `research_question_ids` 显式关联。正式 render 另外检查每个完成专题的正文映射和证据覆盖；机械关联通过仍不能代替对解释清晰程度的独立阅读审查。

## 已授权的外观设计决定书研究

本技能仍以公司技术专利组合为主要对象。用户另行授权外观设计无效决定书研究时，复用上述阅读与质量原则，但采用该任务自己的案件资料结构：一份决定书作为完整阅读任务；其中每项设计、无效理由及证据方案分别记录，保留请求人意见、专利权人意见与审查认定的区别。把涉案图、对比图、组合方式与实际剩余差异对应起来，再比较案件结果。

不要把外观设计或决定书塞入只接受发明/实用新型的 `analysis-import`，也不要为通过八字段校验虚构技术权利要求。案件流程应分别保存全篇阅读、原图核查、独立理由复核和跨案问题记录，并逐项验证；通用技术库的完成结果不能冒称该案件流程已经通过。重新修订已有报告时，沿用有效原文和证据，核清本轮实际重读、复核及比较范围。

案件比较解释的是“哪些可见差异，在什么整体关系和观察情境下，受到怎样的评价”。不套用工程机制、企业技术领先或当前产品侵权结论。按用户已确定的产品细分和研究问题组织；决定书、专利、设计及证据方案分别统计，同一专利多次决定保留程序关系，不当作多个独立成功样本。

跨案基本单位为“具体设计 × 无效理由 × 证据方案”。比较前核对产品、保护对象、争议部位、实际视图、比较基础与认定路径。逐项解释共同前提、可见差异、组合方式及组合后仍然存在的差异，分别绑定涉案图、对比图、原文位置和意见来源。图片必须能显示所解释部位；缺图或视图不对应时保留未核验，不用正确段落替代图像证明。

区分公开或证据基础不成立、组合路径未被接受、进入实体比较后的差异评价，以及未评价的理由；以决定书实际论证为准，不预设每案只落一个原因。同样结果可能来自不同理由，不同结果也可能源于不同证据和争点。不能把“维持”自动解释为设计创新强、把“无效”自动解释为某部位不重要，更不能由这些争议样本估算新案成功率。

重点比较应保留支撑案件、相反或不适用案件、影响结论的其他解释及适用条件。没有相反结果也可以研究理由差异，不强凑正反案例。研究者解释与合议组认定分开：仅存在共现时不写成唯一原因；没有评价的事项不得记为接受或否定。把“某部位重要”落实为该案的位置、比例、周边关系及决定书怎样评价，不抽成无条件的部件权重。

跨案成果可供设计评审、证据检索与论证准备；使用条件和最小补充材料写清，不直接升级为具体新产品的可授权、可实施或必然无效结论。历史决定及后续程序分别核查；当前未查到后续程序不代表不存在。交付验收检查原文、原图、比较理由与限定结论能否相互对应，而不是只检查案例数或引用数量。
