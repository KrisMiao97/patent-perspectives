# 取证与能力适配

在检索或补取专利资料前读取。本文件规定如何确定真实可用能力、建立可对账清单并取得同件全文；不预置某个宿主的工具名称。

## 先检查能力，再启动批量

搜索缺失或用户已有材料时转入[按材料研究](material-research.md)。正文接口缺失可补同件文件或链接；不用虚构提供者总量来通过查询验收。材料模式与全量模式有不同的目录完成条件，技术全文和研究质量条件保持一致。

用宿主原生的工具发现机制搜索 capability：字段检索、主体检索、分页、patent bibliography、description、claims、family、legal status、images、citations。阅读实际工具参数与结果结构，将本次可用服务器和工具映射到运行记录。不能把一次发现的工具数量当作整个服务能力上限。

| 能力 | 最小验证 | 缺失后的处理 |
|---|---|---|
| 字段检索 | 原始/当前主体字段含义，精确匹配规则，分页窗口和排序 | 不能用语义召回结果宣称全量清单 |
| 权利要求（首选主文本） | 完整权利要求集合、引用关系、版本与准确文献身份 | 尝试同件完整说明书或官方同件补证；仍缺则未完成 |
| 说明书 | 完整文本、准确公开号与版本、截断标记、同族替换选项 | 权利要求技术理解充分时无需补读；作为回退也缺失则未完成 |
| 同族和关系 | 同族定义、关系方向、成员标识及来源 | 标为未知，不凭文本相似度生成事实边 |
| 状态 | 原始事件、辖区、数据日期及简化状态含义 | 未知或待官方核验 |
| 图片 | 对应文献、图号、可取得的真实文件或URL | 保留未知，外观单列缺图情况 |

Patsnap 的 Advanced Patent Search 和 Patent Briefing 可能是不同连接，搜索可用不能证明全文已可用。官方能力参考：https://github.com/patsnap/skills 与 https://open.patsnap.com/marketplace/mcp-servers/patent-briefing 。这些地址说明参考来源，实际调用仍由已连接工具验证。

历史预检曾遇到说明书错误 MCP API need a true tool rate!；不能自行解释为限流、额度耗尽或文本不存在。保存原始错误和时间，对可重试的传输错误至多有限次退避重试；鉴权、额度或未解释的服务错误停止该能力批量调用，继续其他独立工作。不得在未验证时写成问题已解决。

用发明、实用新型、旧文献、长文本及不同语言的可得样本测试。分别验证完整 claims 成功、claims 缺失时完整说明书回退、同件说明书按需补读及两者均缺的未完成状态。估算单件调用、耗时和额度，确认有实际依据后才外推；宣传额度与账户实际剩余额度分开。

## 主体与全量检索

以官方披露核验集团根主体、当前及历史受控公司，保存关系、时间、来源和纳入理由。母公司或姐妹公司不得仅因共用品牌并入。主体名称清洗保留原名、别名、历史名和各自来源；企业隶属变化不自动证明逐件权利转移。

分别查询原始申请人和当前登记主体。每条查询保存主体、检索字段、原始请求、范围、执行时间和服务返回总数。当前主体字段的实际含义须核实，不能把当前申请人与经逐件核验的当前权利人混为一谈。

按工具允许的稳定排序完整分页。保留每页完整原始响应及其包装层、offset/游标、记录数和唯一文献号。将服务实际 total_search_result_count 与冻结的 expected_count 核对；没有来源总量只能暂存，不能关闭全量查询。外层或内层错误均保留为错误，不转成空结果。遇结果窗口限制，按不重叠日期、地域或其他支持的字段拆分；对分片边界、总数、重复和漏页核对。服务返回量与唯一文献量、申请量分别记录。语义检索用于补查，不用于替代主体全量查询。

只有全部预期页面与分片对账完成后，才标记 query-complete。检索集合还可能因主体缺失而不完整；查询对账与集团边界确认必须分别通过。

## 同件全文回退

优先同件完整权利要求，完整 claims 不可得时回退同件完整说明书，最后尝试官方对应文献补证。请求时关闭 related/family replacement，并核查返回文献号和版本，不接受服务器以同族文本静默代替。既有已完成完整说明书分析无需因新优先级重复处理。

完整 claims 已能解释技术时，不为补齐未披露的问题或功效读取整份说明书；术语、组成、关系、步骤或机制仍有具体疑问时，只读同一 PN 的相关说明书段落，并保存实际 read_regions 与独立证据归属。辅助说明书也须经过完整来源/身份及拒绝门禁，但局部阅读不冒充主全文完成。不同公开号、公开/授权文本、国家和语言版本不能合并为一份来源。

同一申请的另一版本可以作为技术理解的另一个合法来源，但必须单独登记准确文献身份，重新选择该版本进行分析。不能把公开文本冒称授权文本；讨论授权保护内容时须使用对应授权 claims。

完整性依据须来自结构化文档结束、来源声明的完整内容、原始PDF页范围/总页数或其他可检查信息。字符串足够长、没有省略号或模型声称已读完，均不能单独证明完整。保留全文中的实际权利要求编号行，由脚本确定每项真实起止区间；若另有结构化claims数组，它必须与全文逐项一致。权利要求证据需落在所声明编号的真实区间内。检查连续权利要求编号、文档结束、解析异常和供应商截断标记；这些检查有冲突时保留未完成。

官方补证保留原始URL、获取时间、对应公开号、文件或文本及提取方式。扫描件文字识别若影响关键结构、数字、否定或权利要求关系，须核查原页。官方PDF不可取到完整文本时，保存缺口，不能仅依据摘要关闭任务。

官方本件接口无法取得正文时，可依 [original-document-claims.md](original-document-claims.md) 核验原始公报的固定PDF镜像；须单独标明第三方托管，实际目视准确封面与每页权利要求，并绑定原字节、全页提取、区间和核阅哈希。只有镜像网页或同族链接不通过，不把该路径标成从官方站直接获取。

保留原文排版的技术含义：HTML `sup` 与 `sub` 不能直接去标签后拼接数字。纯文本分别采用显式 `^{原内容}` 和 `_{原内容}`，例如 `10^{4}mm^{3}/s`；记录 normalization_transformations、原标签区间、格式说明和新版本，明确这是提取表示，不是新增原文。空上/下标、丢失公式图片或错嵌套仍需补证，不能推测指数。变更后重新建立文本哈希、chunk 和证据位置；旧分析和旧引文不能无审阅复用。历史有标签的文本先列清单核对实际影响，发现语义损失时保存正式来源拒绝，不因“出现标签”机械批量下结论。

### 正文图片地址为空时的精确补证

正文原 HTML 的 `img-id` 与公式、结构形状、权项引用连接内容同属来源证据。`patent_images` 可能仅包含附图；不能按图片顺序猜测正文公式。已验证可用的 `intelligent_image` 结果中，`data.pdf_images` 可提供正文图片。只有实际文件名与原 `img-id` 完全一致，并且返回的 `patent_id` 与原说明书/权利要求记录一致时，才建立访问绑定；`QLYQS_1` 等无法精确命中的标识仍未解决。

`compose_image_transcription.py` 仅对原标签显式 `src=""` 接受 manifest 图片中的 `supplemental_image_access`，包含原始 Collector 缓存相对路径、SHA256 和实际 `data.pdf_images` 索引。该缓存必须记录 `tool=intelligent_image`、`arguments.pn` 等于当前单一公开号、成功且无外层/内层错误。图片 URL 必须为可信 HTTPS `data-fulltext-image.zhihuiya.com`，文件名精确为原 `img-id` 加图片扩展名，去签名后的 path 必须与 manifest 及已目视审阅记录相等。非空原 `src` 仍必须按其原 path 严格匹配，不能借补充证明改绑。缺少 `src` 属性、近似文件名、同族成员、只有附图列表或仅顺序相似均不通过。

补充访问证明只解决取得路径；仍需下载完整图片、核对文件哈希、逐张目视核验和完整人工转写。输出在 `embedded_image_review.images[].supplemental_image_access` 留存缓存文件/hash、实际索引、来源 `patent_id` 与去签名 path，不将签名 URL 导出到页面。含上下标的原源须先使用已声明的保真新版，补图不能沿用旧压平文本。

法律状态、同族和图片覆盖独立报告。技术全文合格不等于法律状态已核验，法律状态缺失不必抹去已有技术理解。

## 企业边界与初步数量

目标根主体、受控公司与历史名称依本次官方披露核验。上层集团、品牌关联和共同控制不能自动并入。初步搜索匹配数保留原单位和条件，不用作最终独立申请数；全量深析在概览后确认范围，再按清单对账执行。

## Patent Briefing 连接附录

仅在宿主没有发现对应全文能力或需排查连接时使用。先按账号所属平台、已有成功连接及对应官方能力目录核验服务域名，不默认使用某一地区入口。两站公开的 Patent Briefing 地址如下；公开地址本身不证明同一密钥能跨站使用。

| 平台 | 官方能力目录 | Patent Briefing 地址 |
|---|---|---|
| 中国站（专利速览简报） | [智慧芽中国站官方目录](https://open.zhihuiya.com/marketplace/mcp-servers/patent-briefing) | `https://connect.zhihuiya.com/958a46/mcp` |
| 国际站（Patent Briefing） | [Patsnap国际站官方目录](https://open.patsnap.com/marketplace/mcp-servers/patent-briefing) | `https://connect.patsnap.com/958a46/mcp` |

两站均声明 Bearer API 密钥认证。[中国站官方FAQ](https://open.zhihuiya.com/devportal/guides/mcp-faq)说明 MCP Key 与 API Key 是同一个 Key；不能因缺少全文工具就要求另行获取一种“MCP密钥”。宿主MCP支持可参考 [官方MCP接入说明](https://learn.chatgpt.com/docs/extend/mcp)。无需将个人账号配置或密钥打包到技能中。

在本地环境变量中设置 PATSNAP_API_KEY，值仅由用户在本机保存，避免粘贴到聊天、代码、日志或导入文件。然后在支持此TOML格式的宿主配置中加入。以下示例适用于已核验使用中国站的账号；国际站账号须依据上表及实际验证结果替换 URL，其他字段不随意更改：

~~~toml
[mcp_servers.patsnap_briefing]
url = "https://connect.zhihuiya.com/958a46/mcp"
bearer_token_env_var = "PATSNAP_API_KEY"
~~~

环境变量设置或更新后，完全退出并重新启动应用，使新进程继承环境。配置文件存在、地址已填写或用户环境变量存在，都不能证明当前应用进程已经继承凭证，也不能证明本轮工具已经注册可见。

遇到401或 apikey auth error 时，保存脱敏错误、时间和目标域名，先将该域名与账号平台及已有成功服务的域名核对，再检查宿主是否继承变量、Bearer配置和服务授权。某个入口认证失败不能直接解释为密钥本身无效，更不能忽略同一密钥已在另一入口调用成功的事实。公开文档未确认的跨站互通性或错误码含义保留未知；不猜测原因，不要求用户在聊天中提供密钥。可按[中国站快速开始](https://open.zhihuiya.com/devportal/guides/mcp-quickstart)的协议方式验证初始化与 tools/list，再进行业务正文调用；目录发现成功与正文获取成功分别记录。

重启后重新进行工具发现，检查 description、claims、family、status、images 等实际暴露能力，并用同件样本验证权限、返回文献身份和完整性。仅工具可见但未成功取回合格正文时，capability 仍保留 unverified 或 failed；验证成功才记录 verified、checked_at 和可脱敏的 evidence。保持原缓存，通过 export-work 和状态记录续跑，不重复初始化既有运行。

不要读取用户实际配置或环境变量值来制作通用技能包；如排查需要，最多记录“配置是否存在、变量是否可见、测试是否成功”等状态，隐藏值。具体运行受授权、网络和服务配额约束，连接指引不承诺当前会话已接通。
