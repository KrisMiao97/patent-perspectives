# 增量分析与研究快照

在继续既有企业研究、更新资料或比较两轮结果时读取。增量和处理状态写进唯一的《分析记录与后续补充说明》，不在互动报告中增加增量、阶段交付或问题追踪模块。

## 保存什么基线

保留母库、来源、冻结主体与范围、查询口径、研究截止日、逐件证据和已交付版本。快照、数据库备份和网页打包的时间都不是资料取得或法律状态观察时间。继续研究前先核对旧的用户指示，已明确停止的补证不能因新一轮运行自动重启。

`scripts/compare_snapshots.py` 提供只读的结构化快照与差异辅助。它不调用服务、不生成技术结论、不修改数据库，也不代替宿主读取原始来源和判断差异原因。以下路径均由当前任务提供，数据库和输出放在工作区而非技能目录：

```text
python scripts/compare_snapshots.py snapshot --db RUN.sqlite --output snapshot-before.json
python scripts/compare_snapshots.py snapshot --db UPDATED.sqlite --output snapshot-after.json
python scripts/compare_snapshots.py compare --before snapshot-before.json --after snapshot-after.json --output delta.json
```

两次快照使用同一个模式。脚本以 SQLite 只读事务读取一致的已提交视图，记录真实验证状态；技术原文缺失不会伪装成已完成。差异文件仅供统一说明文档和数据复用包引用，不另生成一份重复的人工问题文档。输出文件已存在时拒绝覆盖。

快照保存稳定申请/文献标识、主体/范围/来源/查询计划及登记映射的指纹、文献日期、查询对账、已有法律状态观察、文献/证据/分析/角色结论的内容哈希和依赖。正文仍保存在数据库或数据复用包；快照不会另复制全文、凭证或原始下载地址。`captured_at` 只表示生成快照的时间。`data_sha256` 对快照的数据内容负责，不能用它代替原始公报的字节校验。

## 何时可以称为实际增量

比较时先检查主体、来源、研究范围、查询计划、统计单位和登记映射是否一致。发生改变时单列范围/来源差异，先解释可比性；新增记录不能自动解释成企业新增布局。查询语句或控制关系有合法调整也须保留差异，不能为了通过比较改写旧快照。

分类依据如下：

| 类别 | 需要的证据与表达 |
|---|---|
| 新公开文献 | 两轮同口径目录均对账通过，并有前后两次真实检索观察；该文献在后轮首次出现、归属已核实，实际公开日位于前次截止日之后且不晚于本次截止日。按文献计数，不直接称新增独立申请 |
| 本次新发现的旧公开文献 | 同样有两次可比检索观察，但公开日不晚于前次截止日；记录之前未被纳入，不能称刚公开 |
| 法律状态观察变化 | 同一公开号、相同来源，在实际不重叠的两个观察时间取得不同已知状态。保留两次状态与观察标识；不据此推算法律事件发生日期 |
| 状态证据补齐 | 由未知变已知或冲突记录变化，表述为证据补齐/需核查，不当作已确认的法律事件 |
| 资料纠错或补齐 | 著录、原文、证据、分类或分析内容发生差异。脚本只能找出变动和依赖；宿主须核查来源再判断是纠错、补充、解释调整还是错误 |
| 纯页面修改 | 保持数据基线，另比较资产清单即可。HTML、CSS或打包变化不能冒充新检索或状态观察 |

缺失第二观察时，新增公开和状态变化数量为 `null`，而不是 0。快照内容相同只说明本地所选资料没有变化，不能证明外部没有新增公开或法律事件。日期只有年份、缺失或有冲突时不能补造完整公开日。

脚本中的目录对账是原引擎对主体、查询、候选范围和登记映射相关检查的结果；仍受已冻结数据源与检索规则限制。`review_candidates` 给出可能需要复核的申请、证据和角色结论，不能当作这些结论已经错误的证明。

## 检索观察时间如何绑定

快照默认只读取原始查询页中已有的 `acquired_at` 或 `retrieved_at`，不使用事件导入时间、文件修改时间、网页版本或运行创建时间。许多旧数据库只保存查询返回内容而没有取得时间，此时可比较已保存字段，但不能自动判断新公开增量。

已保留带时间的真实来源缓存时，可提供 `--observation-manifest observations.json`。清单与源文件放在同一工作目录树中，每项指向一张实际查询页：

```json
{
  "pages": [
    {
      "query_id": "真实查询ID",
      "offset": 0,
      "file": "raw/实际缓存.json",
      "sha256": "该缓存文件的真实SHA256",
      "response_path": ["response"],
      "observed_at_path": ["acquired_at"]
    }
  ]
}
```

JSON路径和分页偏移须按实际缓存填写。工具核对文件位于清单目录内、字节哈希、实际返回内容与数据库留存查询页一致，以及取得时间来自指定原始字段；不能手工填写一个较新的时间冒充重查。所有普通查询页均有可核验时间，且后轮最早观察晚于前轮最晚观察时，才视为完整的两次独立检索观察。时间仅精确到日期时保留其区间，重叠日期不强行排序。

观察清单不是取得新数据的授权；本工具不发起查询。清单核验的是资料对应关系，宿主仍需判断原始缓存的可信来源。源缓存经过脱敏导致原始字节不同的，保留原始与导出哈希、转换说明，并使用真实可核验版本，不重写原始取证事实。

## 写回统一说明与复用包

将采用的两个快照标识、截止日、实际检索/状态观察时间、可比性、已确认变化和待核查项写回《分析记录与后续补充说明》。每项问题沿用稳定编号，列出关联申请/文献或市场来源、影响、已经做过的核查、下一步所需材料及文件位置。把 `snapshot-before.json`、`snapshot-after.json` 和 `delta.json` 作为机器可读资料随数据复用包保存。

市场/产品来源的增量也沿用同样的证据原则，但当前快照 helper 主要比较专利数据库。宿主需按市场来源、产品记录的稳定 ID 和实际取得时间另行核查，并汇入同一说明文档；不声称脚本已经自动比较未纳入数据库的市场资料。
