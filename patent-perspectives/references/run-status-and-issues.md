# 分析记录与后续补充说明

在交付、资料补充或增量分析时读取。维护一份可编辑的《分析记录与后续补充说明》，将问题、跳过事项、阶段性交付边界、快照和接续方法集中保存。优先 Markdown；需要其他阅读格式时从同一份内容导出，不维护相互重复的问题文档。

## 与互动报告分开

互动报告呈现产品、技术和三视角分析成果，不增加阶段性交付、运行问题或增量变化板块、目录项、按钮和进度卡。交付入口将互动报告、本说明和数据复用包并列链接，三者采用可移动的相对路径。

主报告仍保留研究截止日、法律状态实际观察日、统计单位、实际分析分母与原文依据。会影响某项指标或技术判断的未知、版本差异和原文歧义，在对应内容旁说明，不能因移出过程信息而隐藏证据不足。企业披露拥有量、已核验公开申请和用于技术解读的申请分别命名。

## 同一文档应包含的内容

- **范围与基线：**主体、日期字段和起止日、公开截止、数据来源、统计单位、原运行状态与本次交付状态、数据版本和快照位置。技术全文、身份核验、法律状态和图片覆盖分别记录。
- **问题与跳过事项：**每项使用稳定编号，保存关联主体/申请/公开号或市场来源ID、当前状态、已完成工作、有效检查与结果、对结论的影响、缺失材料、后续动作及数据文件定位。区分待补证、待核验、已解决和用户明确停止/跳过；记录跳过的适用对象及指示，不能自行扩大豁免范围。
- **修复与纠错：**说明新证据、修复方式和复核结果；原刊差异、提取/OCR错误和本地处理错误分别记录。保留原记录和前后关系，不把旧问题直接删掉。
- **增量分析：**按[增量分析](incremental-analysis.md)记录两次快照与观察时间、比较范围和覆盖、新公开/新发现旧记录/状态观察变化/补齐或纠错/范围变化的区别，以及需重算的申请、图表和结论。没有第二有效时点时说明已建基线与待比较项；页面改版不构成专利数据变化。
- **复用与接续：**指向[数据复用包](data-reuse.md)的主库副本、JSONL/CSV、原文、市场资料和分析字段；说明稳定ID如何关联，哪些记录可直接复用、哪些需重新核验，以及补一件专利、补一条市场来源、开展下一轮分析的步骤。列明脱敏或资料缺失对原始哈希验证与续跑的影响。

可同时保存机器可读的问题清单、冻结清单和差异JSON，使用相同编号并与本说明对账；这些是数据复用包的一部分，不再生成第二份内容重复的人类问题报告。问题按影响组织，不把每次重试都列成新问题。即使没有未解决事项，也写明已完成范围和实际检查边界。

## 有缺口时的交付边界

保留原母库的真实验证状态。用户已明确要求跳过具体事项或按可核验成果继续交付时，直接复用该授权，不重复确认；一般的界面简化本身不授权缩小研究范围。

冻结本次展示清单、未解决清单、适用的用户指示及计数关系。已核验记录可保留在目录，未读技术事项不进入已读结论；主体待核验候选不并入已核验公司统计。逐件正文、引文、版本和分类的质量门槛保持不变。交付可用不代表原运行已全量完成。

先保留完整验证，再验证展示记录及逐项例外。不得屏蔽新错误、改写服务端总数、删除母库候选、按全文可得性偷偷重选范围或把真实资料标成synthetic。普通 `render` 仍要求完整验收；已获授权的缺口交付使用[已审阅例外交付](reviewed-delivery.md)中的 `delivery-draft` 和 `render --delivery-contract --analysis-records`。契约绑定全部业务数据、原错误、上下文和说明，新错误或任何变化都必须重新核查。

## 输出前核对

清单中的ID和数据文件可定位，计划/已读/未读/待核验的数量各自可对账，机器可读记录与文档一致。保留原母库和来源，读者包不包含密钥、临时签名、账号信息或无关机器路径；来源资料输出经过必要脱敏，说明转换范围。完整工具日志与开发测试记录留在工作目录。文件是否可离线打开、整体移动后是否可定位，以及哪些检查未执行，均按实际结果记录。
