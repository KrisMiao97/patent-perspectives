# 公司概览与集中确认

本阶段解决“在看见企业规模后决定分析多少、分析什么”。概要获取由宿主调用当前已授权的专利检索和公开信息工具完成；技能包不内置密钥或供应商专属会话地址。

## 先查哪些事实

检查已有输入、运行及缓存。有明确公司名称时先查法定主体、曾用名和有证据的受控子公司；名称歧义影响范围时先做最小消歧。母集团、品牌、关联方不自动纳入。

概览至少尝试取得以下信息。无法取得的项标明原因，不为凑齐表格估算：

| 内容 | 展示口径 |
|---|---|
| 初步规模 | 列出检索字段、主体、时间和来源；搜索匹配文献数不能称独立申请数或当前拥有量 |
| 专利类型 | 发明、实用新型、外观及未知；有可靠分母才给占比 |
| 状态和地域 | 来源状态及观察日；PCT单列；境外比例先明确本土地域，不能默认所有公司以CN为本土 |
| 时间分布 | 按指定或清楚标注的日期字段；近期公开滞后，不把公开少理解为研发少 |
| 产品/技术线索 | 结合公司产品披露、市售产品和有来源的第三方信息建立产品线索，标明市场、日期及在售/注册/历史等状态；与少量可核查专利内容相对照，初步线索不能冒充全组合技术结论。后续按[产品梳理流程](product-and-ip-observations.md)扩充并分类 |
| 可执行性 | 权利要求/说明书的获取通路、分页限制及未知额度；只做必要的小样本验证 |

概览用一小段事实摘要或紧凑表格即可。保存 `intake-profile.json`：公司、查证时间、主体及来源、查询原文、原始数量及单位、已知类型/地域/时间分布、初步线索、数据可用性与限制。另保存原始响应；不同单位不相加。

## 基于概览集中询问

先展示概要，再把未明确的关键选择放在一次提问中。可合并成一个可自由填写的问题；若界面支持多项，则同一轮发送。以下是选择维度，不是每次都必须问的五个问题：

- **主体**：目标法人、经核验的受控集团成员，或指定主体；说明尚未核验的扩展主体。
- **时间与规模**：所有公开历史、明确日期期间、最近N件技术申请、指定产品范围。提供根据实际规模作出的推荐，不固定推荐3,000件或近五年；日期字段、起止日与截止日写清。
- **重点方向**：全面产品线与技术布局，或用户选择的产品/技术主题。初步线索来自证据，允许用户补充其他方向。
- **读者与用途**：三视角并列或重点面向其中一类；布局变化、技术路线或权利要求/关联案件。单一用途也保留必要事实和证据。
- **地域**：仅在用户用途或已有数据需要明确时询问。若用户已经限定则直接沿用；境外分母单独明确。

可用措辞：“目前已检索到……（单位和范围），主要线索包括……。请一次确认：主体范围；时间/申请数量；重点产品或技术；主要读者。我建议……，依据是……。”没有可用检索连接时先说明获取失败与未知，不编造概览；可基于已有材料集中确认范围。

用户已明确的选择直接列为既定条件，不再提问。用户明确授权采用建议或全量即执行，不再次走确认流程。仅提供公司且范围仍会显著影响工作量时，先等这一轮必要答复；可同时整理主体与来源，不能无答复就启动全量全文。

保存 `analysis-brief.json`：company、entities、filing_window或其他日期口径、cutoff、regions、population_mode、latest_n（如适用）、product_focus、technical_focus、audiences、purpose，以及每个选择来自用户、此前会话还是已说明的默认值。`latest_n`不设置案例常数。若仅分析筛选子集，所有结论都遵循该子集范围。

继续已有任务：先显示当前冻结范围与完成情况；只有本次变更造成新歧义时补问。不要因换了会话重复全套问卷，也不要擅自变更排序和选择清单。
