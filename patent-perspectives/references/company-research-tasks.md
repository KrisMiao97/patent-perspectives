# 围绕目标公司的五类研究任务

需要立项、竞争、画像、选型或预测时读取，沿用已明确主体和时间范围。五类是不同研究问题，不是每次必须逐一运行的步骤。用户要求完整研究时全部覆盖；只要求一项时不扩成全行业全量调查。

## 共同起点

在既有 analysis-brief.json 记录 selected_tasks、目标公司、读者、用途和实际范围。任务标签为 project / competition / profile / selection / forecast。先核查公司法律主体、品牌及母子公司历史关系；不要因新增任务重复询问已明确条件。

以“使用情境—关键功能—工程约束—实现途径”组织研究，再选择主要路线。结合产品核心功能、已读技术内容、工程问题重要性和真实替代方式选择，不只按申请数取前几名。记录每条主要路线的选择理由，未纳入路线与原因留在分析说明；选读范围不能称全部路线。

## 任务方法和交付

| 任务 | 怎样研究 | 必须回答 |
| --- | --- | --- |
| 立项探索 project | 从真实需求和工程约束提出课题，核查现有方案解决到哪里、剩余缺口及实现依赖 | 课题价值依据、候选路线、最小验证方案、继续/暂缓/改题条件。预算和市场资料未知时不虚构回报 |
| 竞争格局 competition | 从相同功能和工况寻找可比企业、供应商及替代技术持有人，说明纳入理由，逐方向核查 | 公司×技术方向矩阵；目标公司的已证位置、差异和未知，不从知名度或数量推总排名 |
| 公司画像 profile | 核对主体、历史申请与当前权利，连贯理解产品线、工程问题、路线和变化，核对产品证据 | 长期解决什么问题、如何实现、改变了什么、能力边界在哪里；技术披露、产品采用、产品表现分别表达 |
| 路线选择 selection | 固定功能、层级、工况、时间、硬约束和评价标准，分别取证再比较 | 条件化推荐、取舍、未知和验证顺序；无可比数据时不强排行 |
| 技术预测 forecast | 从已证状态与瓶颈提出候选变化，检查材料、制造、控制、标准等依赖和反例 | 变化假设、成立条件、观察信号、反证、复核触发器；时间窗口有依据，不把设想写成已发生 |

立项默认是围绕目标公司相关领域提出研究课题，不代表掌握它的内部项目。用户为自身企业立项或选型时，明确目标公司是我方、对手还是标杆；我方成本和产品条件未知时保留条件，不替其做确定投资决策。

## 执行和交付

1. 把用户目的写成可回答的问题，冻结实际范围和主要未知。
2. 用已授权工具取得专利及必要的产品、测试、论文资料，记录查询、时间、过滤、统计口径和覆盖缺口。样本与全量分开；未命中不表示不存在。
3. 沿用完整主文本和独立复核规则。其他公司代表材料不冒充其全量；目录仅支持线索。
4. 对每条主要路线完成[路线研判](route-assessment.md)，用[证据矩阵](evidence-matrix.md)展示关系。
5. 将支持、冲突材料、其他解释和成立条件写入回答。只能回答更窄的问题时保留原问题未解决状态。
6. 专利专题继续进入既有 research-plan-import / research-review-import；外部材料单独复核并保留记录，不伪装成专利申请通过原库门禁。

离线互动报告为主，另附文字稿、机器可读研究数据、来源表和矩阵表。按[industry-data-contract.md](industry-data-contract.md)填写 report-context.json.industry_research；字段校验和页面组件已随包实现。未启用时不影响原报告。

管理层先读课题价值和公司位置；研发先读机制、迁移条件和验证；知识产权先读文献、版本和布局依据。三角色共用事实，逐项权利要求对照仍只在ip界面。新增模块有独立范围说明，不默默继承专利清单筛选。

行业研究JSON、文字稿、来源及矩阵表加入数据复用材料清单，与原文和数据库一起冻结；只保存页面不算证据交付。过程问题仍集中到唯一《分析记录与后续补充说明》。

完成检查：选定任务有答案或明确未知；全部主要路线有四类研判；矩阵可追溯；主体、日期及样本口径一致。新增图表不改变原有全量及独立复核完成状态。

对手的完整原文可通过独立参考语料包关联F/D来源，保留其公司与范围，不混入目标公司专利分母。参考语料的字段和引文通过检查不代表其原始独立审阅已被本程序重新验证，仍须核查实际复核记录。
