# 专利棱镜输出设计规范

更新：2026-11-10。适用于企业专利互动报告，来源为本轮已确认的阅读要求；具体尺寸为实现建议。

## 方向与品牌
- 浅蓝白底、深蓝标题，以可读判断和证据为主体，不做大幅封面。（用户确认）
- 同一份事实，管理层、研发、专利工程师有不同概览和完整路径；概览嵌在当前报告，不另起摘要页面。（用户确认）
- 首屏顺序：公司与业务背景 → 本视角最重要的判断 → 2–3 条理由 → 证据入口。范围只保留理解该判断必需的内容。（用户确认）
- 按章阅读为默认；筛选工作台和主题索引是同一份报告的版式，不能成为三个割裂的功能模块。（用户确认）

## 读者的问题与答案
| 读者 | 首页必须回答 | 证据路径 |
|---|---|---|
| 管理层 | 专利布局主要支持哪些业务？与自身历史相比，集中方向发生了什么变化？有哪些有依据的布局特点？ | 判断 → 产品/年度比较 → 对应申请与公司披露 |
| 研发 | 解决什么实际问题？有哪些具体做法？部件装在哪里、何时动作、需要什么条件？ | 使用情景 → 方法差异 → 代表方案 → 同件原文 |
| 专利工程师 | 哪些权项条件需要关注？比较的是哪个版本？状态和同族关系已核实到哪一天？ | 权项差异 → 要素对照 → 精确版本、原文、状态来源 |

## 内容层级
- 每章必须有证据支持的结论，包括目录、图谱和时间线；操作说明不能占据结论位置。（用户确认）
- 结论解释本次材料显示了什么、与什么相比、读者因此知道什么。数量清单不能替代主要判断。证据不足时说明哪一个问题暂不能回答及缺哪项证据，不补造观点。
- 先结论，再必要解释和图表，再代表案例与原文；全部记录分页，长列表与次要方法折叠。
- 固定结论写明其时间/材料范围。筛选结论从当前同一集合重算；不得把全量文字换标题后冒充子集结论。
- 条件改变结论时就地说明；版本哈希、处理日志、恢复步骤进入来源详情或独立工作说明，不挤占正文。
- 概览与章节结论相同时合并；不得为了满足每章一句而连续重复。

## 数字与术语
- 独立申请：同一申请的公开和授权文献合计一件；跨国同族不自动合并。
- 技术申请：发明与实用新型；外观设计单列。已解读数按实际完成记录计算，不与技术申请数互换。
- 企业披露拥有量、检索目录总量、材料目录总量分别命名，不能相减或混算占比。
- 统一使用产品大类、产品线、技术大类、实现方向、受理机构、技术解读待补齐。申请人和当前权利人有不同含义，不机械全局替换。
- 对读者写“依据完整权利要求解读”，不用“回退”。未读说明书不能写成已读；摘要不算全文。
- 日期显示用途：收录截止、状态观察、企业披露期间。保留原有时间精度和时区。

## 图表与证据组件
- 年度件数优先柱状图，比较走势可用折线图。默认展示近期可比较年份，允许完整历史；不完整年度明确标记。
- 不默认显示满屏零值的大矩阵。确需二维扫描时才使用热图，精确数据放可展开表格。
- 同图同单位和刻度；零与未知区分；分母为零不生成占比。增加、减少、持平文案依据原数值判断，不能比较格式化字符串。
- 图表能进入对应申请清单，结论能进入引用，引用能看到同件同版本原文及位置。
- 权利要求要素对照为共享证据工具，专利视角前置；其他视角可访问。若有角色限制，导航、直达、渲染和原文操作必须一致，不能留下空壳。

## 视觉变量与组件
- 变量和实际取值在 assets/reader/report.css；正文、辅助文字、边框、背景、强调色各有语义变量。（实现建议）
- 正文建议 16px、1.7 行高，长段落约 46em；中文机制说明保留完整句子，不靠缩字号装入卡片。（实现建议）
- 结论采用适度字重与左边线，辅助文字仍清晰。来源哈希不显示在比较卡片中。
- 使用原生按钮、选择框、dialog；触屏目标至少 44px，键盘焦点可见，颜色不承担唯一含义。
- 无装饰性循环动画；展开与切换即时反馈，尊重减少动态效果设置。

## 导航、状态与性能
- 角色切换保留当前章节、筛选、页码和位置，独立“本视角概览”按钮负责回首页。
- 前一章/后一章、当前章节、证据返回路径可见；跨章链接写章节名，不写“上方/下方”。
- 桌面侧栏在手机改成顶部选择框，版式与章节进入正常文档布局，不绝对定位互相覆盖。
- 首次进入有真实内容；不依赖切换选项、缩放窗口或点击第二次才能出现。
- 只渲染当前章节与当页记录，延迟加载大图谱和原文；搜索适当防抖，不复制三份大 DOM。
- 离线交付使用相对资源或自包含文件，不依赖作者电脑的绝对路径、CDN或未打包原文。

## 样板与迁移边界
- 新模板：assets/reader/index.html、report.css、report.js，由 scripts/render_reader.py 生成自包含阅读页面。
- 合成示例：assets/reader/example.json，仅用于测试和查看模板；真实企业、日期、数量和结论必须重新生成。
- 旧 assets/panorama 保留复杂图谱、时间线和既有数据引擎。迁移时复用其真实数据与原文能力，不直接用旧默认页面冒充符合新规范的交付。
- 需要旧模板独有能力时，按本规范完成实际集成和浏览器检查；新阅读模板不是完整分析引擎，也不自动生成研究结论。
