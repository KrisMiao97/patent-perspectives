# 专利棱镜｜企业专利三视角分析

参赛准备版本：2026.10.26-rc1。更新日期：2026-10-26。

把同一套公开专利证据转化为管理层、研发和知识产权三种解读，交付离线互动报告、一份可编辑的《分析记录与后续补充说明》，以及可复用的专利、市场和分析数据包。原始事实、计算结果与分析推断分别保存；角色切换不得改变底层事实。

## 先概览，再集中确认

首次执行先读 [公司概览与集中确认](references/company-intake.md)。只有目标公司无法识别时才先问公司名称或消歧问题；不要一开始就抛出完整问卷。

先利用已授权检索和企业公开资料，简要了解主体、专利规模、类型、地域、年度分布、主要产品/技术线索，以及数据可取得程度。明确哪些是检索匹配文献数、哪些已去重为独立申请；这一步是概览，不逐件下载全量技术全文，也不默认启动全量深析。

把已查到的事实和边界简短展示后，集中询问尚未明确的主体范围、时间口径、全量或子集规模、产品/技术重点及主要读者。给出结合实际规模的建议选项。复用用户已明确的条件和既有运行选择，不重复确认；全部条件已清楚时直接记录并执行。等待必要范围回答时只做不依赖该回答的准备，不把未答复视为同意全量。

## 确定运行边界

先检查已有运行记录与缓存，继续未完成任务。根据已确认选择冻结目标企业、已核验主体、全球或指定地域、时间截止日、数据源及检索规则。新任务的初步概览可查看全球、全部历史公开记录；正式深析的范围以集中确认结果为准。未指定截止日时采用运行开始日，明确告知并冻结；绝不沿用其他企业案例的日期或申请数量。

用户明确收窄到某个申请日期间时，记录首尾均含的起止日和 filing_date 口径。保留母库，以 scripts/derive_scope.py 创建可核验的期间子运行，不删除历史记录或改动原查询服务总数。缺失日期、非法日期或跨期间冲突须待核查，不能以优先权日、公开日或国家阶段日替代。已有效完成的期间内分析复用；正式完成判断采用已确认期间，不能据此宣称历史全量完成。滚动期间图表标明首尾非完整年度及公开时滞，避免把未公开造成的近期数量差异解释成研发变化。

用户要求最近N件技术申请时，读[最近N件范围](references/latest-selection.md)，用scripts/derive_latest.py从已核主体和期间内的完整规范技术申请排名派生。默认申请日降序、同日application_id升序，外观及国家登记成员不重复占名额；不得按全文或完成度选择。母库全行保留，冻结清单可重算核验，续跑使用同一子库。仅所选N件作为本次技术完成分母，不能称企业历史全量。

产品分类前结合实际产品资料与第三方信息梳理产品线；逐件阅读时同步记录可核验的布局和撰写观察。按[产品梳理与知识产权特点观察](references/product-and-ip-observations.md)处理证据、归类和适用范围，报告中呈现产品梳理及知识产权观察，不把公司具体发现写入通用技能。

历史申请与当前持有分别统计。主体须有企业披露等证据；上层集团、共同控制公司和品牌关系不能自动并入。收购前申请、目前持有及已确认转出分别表达。用公开专利分析技术布局，不要求我方内部资料；业务影响、产品实际采用、法律风险或估值所需证据缺失时，保留问题和条件。

## 获取并核验能力

获取数据前读 [acquisition.md](references/acquisition.md)。按当前宿主可用工具发现能力并记录绑定，不预设某个服务器或工具名。Patsnap 的搜索、全文、同族、状态和图片能力可以来自不同已授权连接。

先以分层样本验证完整权利要求、同件说明书按需补读与回退、分页及文献身份，再启动全量。没有完整说明书或完整权利要求获取路径时，继续完成不依赖它的技能和检索准备，保存缺口，不能宣称全量技术分析已经完成。使用现有授权额度，不自动购买。

## 构建共用证据

导入前读 [data-contract.md](references/data-contract.md)。宿主代理承担 MCP 调用、技术理解和角色分析；脚本承担 SQLite 存储、号码与版本关联、覆盖率、统计、校验、页面和打包。脚本不调用额外模型 API。

- 独立申请为逐件技术分析单位；公开及授权文献保留为版本，各国同族成员单独保存。
- 官方国家登记成员与另一次独立申请须区分。只有 [national-registration.md](references/national-registration.md) 的同记录官方身份取证通过后才追加规范单位映射，保留原记录、地域、权属和法律观察及计数桥接；不按一般同族合并，也不把EP全文变成DE全文。
- 发明、实用新型优先取得并读完同件完整权利要求；术语、结构、步骤或工作机制不足以理解时，再补读同一公开号说明书的相关段落。完整权利要求不可得时，回退同件完整说明书；两者均不可得则官方同件补证，仍缺则未完成。关闭自动同族替代。
- 摘要、部分权利要求、截断全文及解析失败不能满足完成条件。主文本逐段处理并核对全部分段覆盖；按需补读的说明书只记录实际已读区间，不冒称全文已读，也不为填补问题、功效空值而强读全文。此前已完成且仍有效的完整说明书分析保留。
- 官方本件接口不能取得正文时，可按 [original-document-claims.md](references/original-document-claims.md) 核验原始公报PDF镜像。单独标明第三方托管、真实公报与内附文献身份，逐页核对完整权利要求；不能采用镜像网页翻译或借同族文本替代。正式页面保留离线原PDF及页码定位。
- 仅依据权利要求时，明确标记依据，分析组成、连接、步骤、条件和范围；未披露的问题、功效、实施细节保留未知。
- 外观设计单列目录、著录和可取得的图片，不纳入技术全文分母。
- 每项技术判断引用同件、同版本的原文位置和可验证短引文。主权利要求和辅助说明书分别保存 document_id、版本、实际读段及证据归属；不混用同族、国家或公开/授权版本。重要结论及图谱边记录证据、适用范围和不确定性。

## 形成三种解读

分析前读 [analysis-roles.md](references/analysis-roles.md)。先做逐件理解，按“产品大类→产品线→技术大类→实现方向”组织；产品用途不明确时单列。计算年度、类型、地域与状态交叉统计，再形成角色结论。分类名称从本次原文产生，不复用其他公司的厨房电器等具体分类。

管理层看规模、类型与地域结构、产品线和技术变化；研发看结构、步骤、条件与路线差异；知识产权看权利要求、关联申请、版本与法律状态。管理层事实区域标题固定为“关键事实”，正文讲已观察事实，不写指挥读者做事的套话。结论与条件必须来自证据，不把相似度直接转成侵权或有效性结论。

权利要求要素对照及公开/授权版本变化只在专利工程师（知识产权，`ip`）界面展示，管理层和研发界面不出现对应板块、导航或选择控件。按[要素对照与版本证据](references/claim-comparison.md)准备真实可比案件，每格定位同件同版本原文；资料不足时区分未披露与未取得，不生成缺证的版本变化结论。普通研发技术路线比较仍按原文解释结构与过程。

## 运行与正式交付

运行入口为 scripts/patent_perspectives.py；先阅读其 --help 及所用子命令帮助，按当前 CLI 的输入格式调用，不猜测参数。可用命令包括 init、entities-import、scope-confirm、capability-import、search-import、query-complete、document-import、export-work、analysis-import、insights-import、relations-import、validate、status、render 和 package。

通过 status 与 validate 追踪清单对账、文本依据、逐件分析、证据及关系。中断后从缓存续跑。语义复核独立抽查跨模块样本，发现系统性问题时重处理受影响批次。

用户要求全量时，只有全量通过才能标记全量完成。仍有缺口时保留真实状态和可恢复数据；用户明确要求跳过具体事项或继续按可核验成果交付时，按[分析记录与后续补充](references/run-status-and-issues.md)整理问题，再按[已审阅例外交付](references/reviewed-delivery.md)生成和审阅冻结契约，用 render --delivery-contract 实际生成成果。不能把未读或未核验事项冒充完成。法律状态核验、同族和图片覆盖分别记录，辅助字段未知不替代全文完成规则。

阶段性交付、过程问题、跳过事项和增量变化集中写入同一份《分析记录与后续补充说明》，不放进互动报告的板块、导航、按钮或进度卡。后续补充优先复用有效证据；按[增量分析](references/incremental-analysis.md)记录真实快照、观察时间、可比范围及受影响结论，不能将界面改版、范围变化或补齐旧资料冒充新公开申请。

报告组织和输入约定见 [reporting.md](references/reporting.md)。准备有证据的 report-context.json，调用 render --report-context FILE；通用页面与统计脚本已随包提供。企业名、年份、地域口径、产品分类和所有数量由本次数据生成。

页面沿用浅蓝白色、蓝色标题和清晰卡片。首屏按读者问题与证据完整性选择指标，不固定放置缺失的拥有量或类型占比；企业披露与检索目录分别标明时期、单位和分母，不混补缺失分项。三种角色各有导读和完整阅读路径，管理层前置产品与业务演进，研发解释结构、过程与条件，知识产权组织版本、要素和有证据的观察。按[读者路径与阅读验收](references/reader-acceptance.md)安排内容层级、桌面及窄屏目录、年度类型与产品联动、图表问题与追溯、时间轴首件边界，并完成独立阅读审查。

技术时间图默认采用[紧凑阅读](references/compact-timelines.md)，按有展示节点的年份排列可读卡片，减少空白；保留按时间比例、缩放和全屏。两种视图沿用同一节点、日期口径、筛选、分页与原文入口。

产品年度表采用定量色阶。每个技术大类和实现方向有技术梳理和时间入口；重要技术总图、产品事件图、逐线技术图、可全屏的分层思维导图以及原文详情共用筛选。每个图标明筛选适用范围，固定文字结论保留原始范围。

正文、标题、弹窗、图注及随包说明不得包含“用户提供”“参考PDF”“Skill未修改”等内部开发记录；主报告保留研究截止日、实际状态观察日、统计单位、实际分析分母和影响具体结论的证据限制。详细处理覆盖、跳过原因及恢复步骤只进入独立说明。检查真实浏览器下的离线打开、目录移动、筛选、角色切换、图谱和原文跳转；要素对照另查角色隔离与直达入口。权限受限时如实记录未完成的显示验证，静态检查不能冒称浏览器测试通过。

通常交付互动报告与总览图、唯一可编辑的《分析记录与后续补充说明》、数据复用包，以及将三者并列链接的阅读入口。按[数据复用交付](references/data-reuse.md)输出实际收集的专利著录、文献与原文、市场/产品资料、分析及证据；保留稳定ID、来源与观察日期、字段说明、快照和文件清单，采用SQLite一致性副本及必要JSONL/CSV和相对资产路径。原母库保持可恢复；脱敏副本的校验范围和续跑限制明确记录，不把网页当作唯一数据交付。原始工具日志与开发验证记录留在工作目录；可复核来源材料与日志分别处理。技能包与企业运行数据分开，凭证和临时签名不进入交付。需要分发技能或参赛时再附技能ZIP和作品说明，原创边界见 [ORIGINALITY.md](ORIGINALITY.md)。
